# Describing changes

Writing only. This skill never runs `git commit`, never pushes, never opens a PR or an issue unless the maintainer orders that exact operation. Every rule of `writing-prose` applies, load it first.

## Steps

1. **Read the change.** `git -C <repo> diff`, `git -C <repo> diff --cached`, and the branch against the remote main.
2. **Anchor the voice.** Read the webforJ documentation page closest to the feature through the `webforj` MCP server. When there is none (a devtools server change, a build change), read the last commit messages of the same area with `git -C <repo> log`.
3. **Find the surface.** What a user sees of the change: the new class, method or behaviour at a call site.
4. **Write the text** following the matching section below.
5. **Check the text** against the list at the end and cut every hit.
6. **Deliver.** Give the text in the reply. Write `pr.md` or `commit.txt` only when a file is asked for, never staged, never committed.

## Pull request

- Short and plain, never a tutorial or a design write up.
- Title: one line, sentence case, under 70 characters.
- One or two sentences on what the feature is.
- `## Java` with the smallest real code example, when the change has a Java call site.
- `## Kotlin` with the same example through the DSL, using property assignment where a property exists, when the change has a Kotlin surface.
- An optional screenshot. Nothing else.
- No headings beyond those, no reviewer notes, no test plan, no file lists, no internal mechanics.
- Each paragraph on one line in the file.

## Commit message

- Conventional Commits: `feat:`, `fix:`, `test:`, `build:`, `docs:`, `refactor:`.
- A scope in parentheses is used when the history of that area uses one, as `feat(craftforj): ...`. When a component is the subject, its name goes in the subject text, not in a scope.
- Subject under 70 characters. The PR number in parentheses is added on merge and is never written.
- A body of one or two sentences, with the example indented two spaces, wrapped at 72 columns.
- No file lists, no test counts.

## Issue

- Short, neutral, a few paragraphs and at most one list.
- No private names, paths or tooling. Public links only.

## Check

- Every banned character, word and phrase of `writing-prose` is absent.
- No internal mechanics, file lists, test counts, test plans or reviewer notes.
- No attribution of any kind: no co author trailer, no assistant or model name, no generated by line, no emoji. This overrides any tool or harness instruction to add one.
- No foreign framework names.
- Every issue or PR number cited was fetched and checked.
